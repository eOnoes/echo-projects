Bottom line: The prior ternary attempt failed because we applied a ternary storage format to a model that was never trained to be ternary. The fix is mixed-precision quantization — trim the weights that tolerate it, protect the ones that don't — plus getting the fine-tune/quantize order right.

Why this project exists

A prior effort quantized Phi-4-mini-instruct to ternary with no training.

It produced genuinely useful failure evidence — including layer-0 localization showing where the collapse begins — but no usable model. The conclusion recorded at the time was blunt:

No-training strict ternary is not useful yet.

We now know why, and the answer is fixable. That makes this worth reopening rather than writing off.

What the research audit found

PROVEN Scalar PTQ methods (GPTQ/AWQ class) plateau at 3–4 bits per parameter. Below that, quality degrades sharply.

PROVEN Microsoft's BitNet b1.58 2B4T uses native ternary weights trained from scratch. It was never quantized post hoc.

PROVEN TQ1_0 = 1.6875 bpw and TQ2_0 = 2.0625 bpw are packing formats introduced to store TriLM/BitNet-style ternary models.

PROVEN Per-tensor mixed precision in standard GGUF form is a shipped technique.

PROVEN Unsloth now has native QAT via TorchAO, recovering up to ~70% of lost accuracy. Schemes: int4, int8-int4, fp8-int4. Floor is 4-bit.

INFERRED A working reference recipe exists: LoRA → merge → selective QAT (~250 steps) → AWQ.

The correction to our mental model

We had been treating "ternary" as the goal. The research says treat it as the aggressive end of a spectrum.

Uniform ternary, no training   →  catastrophic (what we did)
Uniform learned 2–3 bit        →  viable
Per-tensor mixed precision     →  better at equal average bits
4-bit QAT with LoRA            →  best quality per bit, 4-bit floor
True ternary + distillation    →  separate research project

So we are not abandoning ternary. We are giving ourselves a dial instead of a switch.

The training order — your question, answered

It depends entirely on how far you compress.

TargetCorrect orderWhy
4-bit and aboveFine-tune → quantizePTQ holds up fine here
2–3 bitFine-tune → learned quantizerPlain rounding isn't enough
~1.58-bit ternaryQuantize during trainingThey cannot be separated

Practical answer for us: fine-tune first in FP16, then apply mixed-precision quantization. That order is legitimate and it is not the same mistake as before, because most tensors stay above ternary.
